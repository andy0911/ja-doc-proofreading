# 書く前の準備（ja-proofread：書く前）

AIが書いた文章は、語句よりも構成の型で見抜かれます。読者役テストでは、言葉を直しても「AIっぽい」という印象がほとんど変わらず、原因は同じ形の節の反復、3点ぞろえ、決め台詞でした。書いてから直すより、書く前に避けるほうが安く済みます。

## 1. 台帳を読む

このスキルのディレクトリから見て `../../data/ledger.json` が台帳です。`status` が `active` の型をすべて読み、とくに `category` が「構成」の型と `detect.type` が `review` の型を頭に入れてから書きます。一覧だけ見たいときは次を実行します。

```bash
node "<このスキルのディレクトリ>/../../scripts/ledger.mjs" list
```

## 2. 書く前に決めること

書き始める前に、次の3つを1行ずつメモにします。メモは文書には入れません。

- 読者は誰か。その人は何を知っていて、何を知らないか。
- 読み終えた読者に、何を決めてほしいか、何をしてほしいか。
- 読者が読まずに飛ばしても困らない部分はどこか（そこは削る候補です）。

## 3. 書くときの約束

台帳の型を避けるための、書き方の約束です。

- ゴール（読者に決めてほしいこと・してほしいこと）を、本文の最初の段落に書く。発表者ノートだけに書かない。
- 項目の数は中身で決める。「3つの〜」とそろえない。2つなら2つ、5つなら5つ書く。
- 同じ形の節を4つ以上並べない。並べたくなったら、表にまとめるか、大事な節だけ詳しく書く。
- 節の最後を決め台詞で締めない。最後の文は、次にすること・数字・条件のどれかにする。
- 「AではなくB」は文書全体で2〜3回まで。言いたいBを先に書く。
- 誰も言っていない「古い考え」を立てて倒さない。対比するなら、実在の前提を出典つきで書く。
- 断り書き（「説明用の例です」など）は冒頭か巻末に1回だけ書く。
- 「注意：」「例：」のようなラベル＋コロンの行を続けない。文の中に入れる。
- カタカナ語は4つ以上並べない。読者がふだん使う日本語に言い換える。
- 「右の図」「下の表」と書かない。図表に名前をつけて、その名前で呼ぶ。
- 成果物は名詞の羅列で説明しない。完成した物の見た目を1文で書く。
- 数字・固有名詞・引用には出典を添える。確かめていないことは、確かめていないと書く。

## 4. 書き終えたら

`proofread` スキルで校正します。自分で書いた文章を自分で採点すると甘くなるため、独立したレビュー役と読者役は必ず別のサブエージェントに任せます。
