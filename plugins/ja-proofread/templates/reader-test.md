# 読者役テスト（フレッシュアイズテスト）の進め方

## 1. 問いを先に作る

テストの前に、書き手（あなた）が理解度の問いを5〜8問作ります。答えも書いておき、読者役には見せません。

- 問いの半分は「この資料は読者に何をしてほしいか」「いちばん大事な数字は何か」のような要点を聞くもの
- 残りは、誤解されやすい箇所を狙うもの（成果物の中身、条件、例外など）

## 2. 読者役を選ぶ

2〜3体を、別々の `fresh-eyes-reader` サブエージェントとして起動します。1体は必ず「AIの文章に抵抗がある読者」にします。

人物像の例：

- AIの文章に抵抗がある読者：「AIで作った資料は中身が薄いと思っている。決まり文句や整いすぎた構成を見ると読む気をなくす。〇〇の担当で、△△は知っているが□□は知らない」
- 忙しい決裁者：「この資料で決めることだけを知りたい。3分で読み終えたい」
- その分野に詳しくない新人：「専門用語やカタカナ語はほとんど知らない」

対照を置くときは、直す前の版を読む読者役を1体足します。同じ人物像にします。

## 3. 渡すもの

- 対象の本文（ファイルのパス）
- 人物像
- 理解度の問い（答えは渡さない）

書き手が誰か、AIを使ったか、校正したか、何をテストしているかは渡しません。先入観が入るからです。

## 4. まとめ方

| | 読者A | 読者B | 読者C（対照） |
|---|---|---|---|
| 理解度（正答数） | | | |
| 信頼度（1〜5） | | | |
| 書き手の推定 | | | |

- 自由回答のうち、2体以上が同じ所を挙げたものは、直す優先度を上げます。
- 台帳のどの型にも当たらない自由回答は、grow-ledger スキルの候補にします。
- 読者役はLLMです。実際の人の反応とは限りません。点数の差が小さいときは「差が検出できなかった」と書きます。
